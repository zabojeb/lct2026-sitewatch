# YOLO 640 / YOLO 960 → ConvNeXt-small

Два последних детектора YOLO26x, дообученных с новым архивом, и последняя ConvNeXt-small. Детекторы находят один класс `object`; ConvNeXt определяет категорию каждого найденного bbox. Классификатор обучен с season + геометрия + погода + камера, включая данные нового архива и класс drilling_rig.

## Файлы

- `weights/yolo_640.pt`: лучший checkpoint эпохи 1 из 8, размер входа 640.
- `weights/yolo_960.pt`: лучший checkpoint эпохи 22 из 29, размер входа 960.
- `weights/convnext_small_latest.pth`: последняя ConvNeXt-small, лучшая эпоха 1 из 7, 22 известных класса + unknown.
- `predict.py`: полный инференс с отрисовкой bbox, классификацией и измерением времени.
- `reject_threshold.json`: порог unknown именно для этих весов; не заменять порогом старого классификатора.
- `class_names.json`: соответствие ID и классов классификатора, ID с нуля.
- `manifest.json`: контрольные суммы весов и настроек.
- `wheels/`: версия Ultralytics, с которой модели обучались и проверялись.

## Установка

Распакуйте ZIP и перейдите в папку `jepa-models-2026-09-28`. Используйте Python 3.10–3.12; скрипт также проверен в существующем окружении Python 3.9 / PyTorch 2.8.0.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

В Windows активируйте окружение командой `.venv\Scripts\activate`.
Установка зависимостей требует интернета; сами веса включены в архив, при инференсе скачивать их не нужно. Для NVIDIA используйте сборку PyTorch 2.8.0 / torchvision 0.23.0 с CUDA, совместимой с вашим драйвером. `--device auto` выбирает CUDA, затем Apple MPS, затем CPU. Через `--device cpu` можно принудительно выбрать CPU.

## Запуск

YOLO 640 и классификация всех найденных bbox:

```bash
python predict.py --source /path/to/photos --model 640 --output results_640
```

YOLO 960:

```bash
python predict.py --source /path/to/photos --model 960 --output results_960
```

Также поддерживаются отдельная фотография и ZIP с изображениями, в том числе с вложенными папками:

```bash
python predict.py --source "Строительная_техника.zip" --model 960 --device cuda:0 --output archive_960
python predict.py --source image.jpg --model 640 --device cpu --output single_image
```

Для просмотра слабых детекций и отклонённых объектов:

```bash
python predict.py --source /path/to/photos --model 960 --conf 0.10 --show-rejected --output review_960
```

`--limit 20` ограничивает число изображений; `--batch-size 16` задаёт пакет кропов ConvNeXt. Выходная папка должна быть новой или пустой. Порядок обработки — лексикографическая сортировка путей.

## Что сохраняется

- `annotated/*.jpg`: фотографии с bbox и названием класса.
- `predictions.json` и постепенно записываемый `predictions.jsonl`: **все** найденные bbox, включая unknown/person; координаты `xyxy` в пикселях после применения EXIF orientation, ID/имя класса, вероятности, причина фильтрации и топ-3.
- `latency.csv`: время декодирования, YOLO, подготовки кропов, ConvNeXt и полного прохода без рисования/записи файлов.
- `config.json`: версии библиотек, SHA256 весов, устройство и параметры инференса.
- `run.log`: живой вывод, прогресс по изображениям, предупреждения и полные ошибки.
- `COMPLETE.json`: появляется только после успешного завершения всех изображений.

## Правила классификации

По умолчанию YOLO использует confidence ≥ 0.25, IoU=0.7, max_det=300, квадратный вход 640/960, FP32. Не меняйте 640 на 960 простым изменением разрешения: выбирайте соответствующие веса через `--model`.

Для каждого bbox берётся полный кроп без дополнительных отступов: floor для верхнего левого угла, ceil для нижнего правого, обрезка по границам кадра. ConvNeXt получает RGB 224×224 с сохранением пропорций, padding=114 и нормализацией ImageNet из checkpoint. Искажения пропорций и аугментаций при инференсе нет.

Если `p_unknown > 0.011581308208405972`, результат считается unknown. Иначе выбирается самый вероятный из 22 известных классов. Unknown и person не рисуются по умолчанию, но остаются в JSON (`retained=false`); `--show-rejected` показывает их красным. Для unknown сохраняется также `best_known_name` — это кандидат, а не принятый класс.

Порог unknown выбран на validation и может быть значительно ниже 0.5. Это не порог уверенности YOLO. `detector_confidence` и `class_probability` — разные величины. Их произведение записывается в `combined_score` для известного класса, но дополнительная фильтрация по нему не выполняется. Дополнительного NMS между классифицированными bbox нет.

Прогрев выполняется до замеров. Времена зависят от устройства, числа bbox и размера пакета; локальные времена нельзя считать latency на H100. Порог unknown калибровался с CUDA BF16; FP32 на другом устройстве может дать небольшие численные отличия у границы порога.

Состав этого пакета: два общих детектора и классификатор. Специалист по башенным кранам в пакет не входит.
