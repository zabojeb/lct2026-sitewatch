# SiteWatch — запуск для команды

Этот архив содержит исходный код прототипа, семь демонстрационных сцен, два режима распознавания и все четыре файла модели. Docker Compose поднимает три локальных контейнера: веб-интерфейс, YOLO + ConvNeXt и сервис проверки правил. База данных для демонстрации не требуется.

## Быстрый старт

1. Распакуйте ZIP в обычную папку. Не запускайте проект прямо внутри архива.
2. Установите и запустите **Docker Desktop** (Windows/macOS) или Docker Engine с **Compose v2** (Linux). При первом запуске нужен интернет для загрузки базовых образов и зависимостей.
3. Запустите:
   - **Windows:** дважды щёлкните `start.cmd`;
   - **macOS/Linux:** в терминале из этой папки выполните `bash start.sh`.
4. После сборки откройте [http://localhost:3000/](http://localhost:3000/). Основной экран анализа: [http://localhost:3000/app/model](http://localhost:3000/app/model).

Для остановки используйте `stop.cmd` или `bash stop.sh`. Следующий старт повторно использует собранные образы. Если порт 3000 занят, измените `SITEWATCH_WEB_PORT` в `.env.demo` и запускайте снова; адрес в сообщении скрипта изменится соответственно.

## Что проверить

1. На экране «Анализ сцен» откройте готовую сцену или загрузите свои JPEG/PNG/WebP. Можно выбрать один файл, несколько или папку до 20 кадров.
2. Выберите **Recognition Medium** (YOLO 640) либо **Recognition Max** (YOLO 960) и нажмите «Распознать». Первый запрос после запуска может быть заметно медленнее.
3. Выберите кадр: рамки и классы техники должны появиться поверх снимка. Модель описания автоматически называет видимые работы на выбранном кадре; отдельное сравнение с плановой работой открывается в блоке результата.
4. Откройте «Архив → Кадры». Запуски сохраняются **локально в браузере** вместе с уменьшенными копиями изображений. Готовые демонстрационные проекты и сценарии плана показаны отдельно.

Новые веса являются детекторами **рамок объектов**, не масок сегментации. Класс техники определяется отдельной ConvNeXt-моделью. Демонстрационные «задержка» и «опережение» в архиве рассчитываются по заданным датам сценария; это не автоматическое измерение реального графика.

## Ключ для описания работ

Описание работ на кадре делает мультимодальная модель через OpenAI-совместимый API (chat completions с изображением). Создайте рядом с `compose.demo.yaml` файл `.env.demo`:

```
DESCRIBE_API_URL=https://…/v1/chat/completions
DESCRIBE_API_KEY=ваш_ключ
DESCRIBE_MODEL=идентификатор_модели
SITEWATCH_WEB_PORT=3000
```

Ключ передаётся только веб-контейнеру: браузер обращается к своему серверу, а тот — к модели описания. Распознавание техники и сервис правил работают без ключа. `.env.demo` не коммитится (`.gitignore`). Внутренний токен между контейнерами скрипт запуска создаёт заново при каждом старте.

## Если что-то не поднялось

- Проверьте, что Docker Desktop запущен и выделено достаточно ресурсов для PyTorch и трёх контейнеров.
- Посмотрите состояние: `docker compose --env-file .env.demo -f compose.demo.yaml ps`.
- Посмотрите последние ошибки: `docker compose --env-file .env.demo -f compose.demo.yaml logs --tail=100`.
- Если сайт открывается, но кнопка распознавания неактивна, подождите готовности inference-контейнера и обновите страницу. Веса сверяются по SHA-256 при старте.
- Если распознавание работает, а визуальное описание нет, проверьте адрес, ключ и лимиты модели описания. Работа детектора от неё не зависит.

Ни исходные снимки, ни архив запусков не синхронизируются между компьютерами. Для общего командного архива потребуется серверное хранилище; текущий пакет предназначен для локального показа и проверки прототипа.
