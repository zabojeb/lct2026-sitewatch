# Сопоставление этапов строительства и техники

## Назначение

Алгоритм переводит название строки календарного плана в проверяемый профиль техники. Он рассчитан на внешний видеомониторинг площадки и не пытается контролировать ручные, внутренние или кратковременные операции по одному кадру.

## Поля результата

- `required`: каждый класс должен появиться в пределах окна наблюдения.
- `required_any`: достаточно хотя бы одного класса из каждой альтернативной группы.
- `optional`: техника допустима для технологии, но её отсутствие не является отклонением.
- `camera_control`: включается, если заполнены `required` или `required_any`.
- `observation_window_minutes`: рекомендуемое окно агрегации детекций. Требование не означает присутствие машины на каждом кадре.
- `match_status=needs_review`: алгоритм не нашёл достаточного основания. Такая строка не получает фиктивный набор техники.

## Алгоритм

1. Название нормализуется: регистр, `е/ё`, пробелы и варианты тире.
2. Точные укрупнённые заголовки сопоставляются отдельно и не получают жёстких требований.
3. Короткие неоднозначные названия инженерных сетей разбираются с помощью контекста `l1/l2`. Например, «Прокладка кабеля» во внутренних сетях не контролируется внешней камерой, а в благоустройстве относится к наружной траншее.
4. Специфичные регулярные выражения проверяются по приоритету. Границы слов исключают ошибку `кладка`/`прокладка`.
5. Для общих строк известных разделов применяется консервативный профиль без необоснованных обязательных машин.
6. Неизвестное название получает `needs_review`.

## Классы техники

К восьми классам из технического задания и трём ранее добавленным классам добавлены:

- `погрузчик`: нужен для погрузки мусора/грунта и присутствует в ресурсных таблицах ГЭСН;
- `автогрейдер`: ведущая машина планировки земляного полотна и дорожного основания;
- `асфальтоукладчик`: ведущая машина устройства асфальтобетонного покрытия.

Итого используется 14 канонических классов. Добавление класса в справочник не означает, что детектор уже обучен его распознавать: перед включением предупреждений класс должен быть подтверждён тестовой выборкой CV-модели.

## Официальные основания

ГЭСН не содержит готовой таблицы «произвольное название этапа → класс компьютерного зрения». Он содержит состав операций и ресурсы «Машины и механизмы» для конкретных сметных норм. Профили в этом проекте являются воспроизводимым обобщением этих ресурсов для видеоконтроля.

- Минстрой России, ФСНБ-2022 / ГЭСН 81-02-01-2022: земляные работы, разработка грунта с погрузкой на самосвалы, автогрейдеры и уплотнение. https://minstroyrf.gov.ru/trades/tree_download.php?ID=0&folder=fsnb2022
- Минстрой России, ГЭСН 06: монолитные бетонные и железобетонные конструкции; таблицы 06-01-003 и 06-22-004 используют автобетононасосы, башенные краны и бортовые автомобили. https://minstroyrf.gov.ru/docs/137985/
- Минстрой России, ГЭСН 07: сборные железобетонные конструкции; таблица 07-05-004 содержит башенные и автомобильные краны. https://minstroyrf.gov.ru/trades/dwd-state-gesn.php?ID=6
- Минстрой России, ГЭСН 27: дорожные основания и покрытия; таблицы 27-03-002/003 содержат автогрейдеры и катки, таблица 27-06-039 — асфальтоукладчик и катки. https://minstroyrf.gov.ru/trades/dwd-gesn-2020.php?ID=26
- Правительство Москвы / Москомэкспертиза, приказ МКЭ-ОД/23-89: официальный перечень сборников ТСН-2001, включая земляные, свайные, бетонные, дорожные, тоннельные работы и озеленение. https://www.mos.ru/upload/documents/files/5683/MKE-OD-23-89sprilojeniem.pdf

## Запуск

Пересборка таблиц напрямую из Excel:

```bash
.venv/bin/python data/build_stage_equipment_map.py
```

Проверка нового этапа без изменения Excel:

```bash
.venv/bin/python data/build_stage_equipment_map.py --stage "Устройство асфальтобетонного покрытия"
```

С контекстом раздела:

```bash
.venv/bin/python data/build_stage_equipment_map.py --stage "Прокладка кабеля" --l2 "Благоустройство территории"
```

Тесты:

```bash
.venv/bin/python -m unittest data/test_stage_equipment_mapper.py
```
